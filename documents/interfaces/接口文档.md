# CS5481 项目数据接口

版本：`v2.0`  
状态：M1 已定义，其他阶段待对应成员补充

本文档定义各阶段之间的数据交接格式。实现代码可以各自独立，下游只依赖这里已经
确认的文件契约，不读取上游的内部变量或临时数据库。

## 1. 分工与状态

| 阶段 | 负责人 | 当前状态 | 主要输入 | 主要输出 |
| --- | --- | --- | --- | --- |
| M1 数据采集 | M1 | 已定义 | Guardian API | Raw JSONL、Documents JSONL |
| M2 Chunking | M2 | 待补充 | M1 Documents | 待 M2 定义 |
| M3 Embedding | M3 | 待补充 | M2 Chunk | 待 M3 定义 |
| M4 Retrieval | M4 | 待补充 | M3 向量库 | 待 M4 定义 |
| M5 Generation | M5 | 待补充 | M4 检索结果 | 待 M5 定义 |
| M6 Evaluation | M6 | 待补充 | QA 集及生成结果 | 待 M6 定义 |

## 2. 通用约定

- JSONL 使用 UTF-8，每行一个 JSON 对象。
- 每条记录必须包含稳定主键和 `schema_version`。
- 引用必须保留原文 URL、标题和发布时间。
- 文件格式不兼容变更时升级 `schema_version`，并更新本文档。
- 交付数据时同时提供 manifest，记录数量、参数和 SHA-256。

## 4. M1：新闻文档

### 4.1 输出文件

```text
data/raw/guardian/articles.jsonl
data/documents/documents.jsonl
data/manifests/documents.manifest.json
data/manifests/raw_articles.manifest.json
```

`data/state/guardian.sqlite3` 是 M1 私有状态，不属于下游接口。

以上文件的说明见 [M1 README](../../scripts/m1_data_preparation/README.md)。

### 4.2 标准文档

路径：`data/documents/documents.jsonl`  
版本：`news_documents.v1`  
Schema：`documents/interfaces/schemas/documents.schema.json`  
主键：`document_id`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema_version` | string | 固定为 `news_documents.v1` |
| `document_id` | string | 文章唯一 ID |
| `url` | string | 原文 URL |
| `title` | string | 标题 |
| `body_text` | string | 完整正文纯文本 |
| `body_html` | string | 完整正文 HTML |
| `byline` | string | 作者 |
| `section_id` / `section_name` | string | 栏目 |
| `published_at_utc` | string | ISO 8601 UTC 发布时间 |
| `fetched_at_utc` | string | 实际抓取时间 |
| `language` | string | 语言，当前为英文 |
| `word_count` | integer | whitespace-delimited word 数 |
| `content_sha256` | string | 正文归一化后的 SHA-256 |
| `metadata` | object | 其他来源元数据 |

文档必须唯一，正文必须是全文。下游应使用
`url`、`title`、`published_at_utc` 构建引用。

M1 请求使用 Guardian `first-publication` 日期筛选。请求日期窗口和实际返回时间戳
可能相差一个 UTC 日，报告时应以 manifest 中的实际日期范围为准。

### 4.3 重跑

重复运行 M1 抓取脚本即可。SQLite 状态库按文章 ID、URL 和正文哈希去重，已有文章
更新，新文章追加；随后运行 `build_documents` 重新生成完整文档。

具体命令见 `scripts/m1_data_preparation/README.md`。

## 5. M2：Chunking（待补充）

M2 接收：

```text
data/documents/documents.jsonl
```

M2 补写本节时应明确：

- chunk 文件路径和 `schema_version`；
- `chunk_id`、`document_id`、`chunk_index` 的定义；
- chunking 参数及可复现条件；
- chunk 文本和 citation 字段；
- chunk manifest 的格式。

下游需要能够仅凭 chunk 记录定位原文，不必回读 M1 的内部数据库。

## 6. M3：Embedding 与向量库（待补充）

M3 接收 M2 的 chunk 数据。补写本节时应明确：

- embedding backend、模型名和版本；
- 向量库类型、路径和集合命名；
- 向量 metadata；
- 索引 manifest；
- 模型变化时如何创建新索引。

## 7. M4：Retrieval（待补充）

M4 接收 M3 的向量库。补写本节时应明确：

- `retrieve()` 的输入和返回类型；
- top-k、日期或 metadata 过滤参数；
- 每条结果的 chunk 文本和 citation；
- 单次检索与批量检索的输出格式；
- 延迟测试结果格式。

## 8. M5：Generation（待补充）

M5 接收 M4 的检索结果。补写本节时应明确：

- Prompt package 格式；
- 检索结果到 `[S1]`、`[S2]` 引用标签的映射；
- LLM 输入、输出和模型信息；
- 引用校验与 `INSUFFICIENT_SOURCES` 拒答格式。

## 9. M6：Evaluation（待补充）

M6 接收 M4、M5 的结果。补写本节时应明确：

- QA 集 schema；
- 检索命中率、答案正确性、引用准确率和拒答准确率；
- 实验结果表格式；
- Demo 输入输出。
