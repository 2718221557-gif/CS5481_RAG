# M2 文本切分（Chunking）

## 运行方法

在仓库根目录运行：

```bash
python -m scripts.m2_chunking.chunk_documents
```

脚本读取 `data/documents/documents.jsonl`，在 `data/chunks/` 下生成三种切分结果。每个 JSONL 文件都有对应的 manifest，记录输入和输出文件的 SHA-256、参数、文档数、chunk 数及词数统计。

## 三种切分策略

| 文件 | 策略 | 默认设置 | 特点 |
| --- | --- | --- | --- |
| `chunks_A.jsonl` | 固定长度并重叠 | 每块最多 1,200 字符，重叠 150 字符；尽量在句子边界切分 | 重叠部分帮助保留块边界处的上下文，但会重复文本、增加 embedding 和存储开销，也可能切开自然段落。 |
| `chunks_B.jsonl` | 段落优先 | 每块最多 1,200 字符；超长段落优先按句子拆分，必要时按字符拆分 | 尽量保留段落语境、不主动重叠；依赖输入中的段落边界，超长段落会触发后备切分。 |
| `chunks_C.jsonl` | 句子优先并附标题 | 每块最多 1,200 字符；每块前面附上文章标题 | 通常保持句子完整，并给每块补充文章主题；标题会重复，超长句子仍需后备切分。 |

可通过 `--chunk-chars` 调整 A、B、C 的字符上限，通过 `--overlap-chars` 调整 A 的重叠字符数。例如：

```bash
python -m scripts.m2_chunking.chunk_documents --chunk-chars 1000 --overlap-chars 120
```

A 的重叠值必须小于字符上限。B 和 C 不使用重叠参数。

## 输出字段与 M3 对接

每条记录使用 `news_chunks.v1` schema，包含：

- `chunk_id`：由文档 ID、策略、块序号和文本生成的稳定 ID。
- `document_id`：原始文档 ID。
- `chunk_index`：文档内从 0 开始的块序号。
- `strategy`：切分策略名称。
- `text`：用于 embedding 的文本。
- `word_count`：按空格分隔统计的词数。
- `citation`：原文 URL、标题、发布时间和来源信息。
- `metadata`：可用的栏目、语言等文档信息。

M3 应对 `text` 做 embedding，并保留其余字段作为向量 metadata，供检索结果和后续引用使用。

## 当前数据统计与方法比较

本次输入包含 3,152 篇文档，三种策略的结果如下：

| 策略 | Chunk 数 | 平均词数 |
| --- | ---: | ---: |
| A 固定长度 + 重叠 | 17,015 | 169.11 |
| B 段落优先 | 15,914 | 159.13 |
| C 句子优先 + 标题 | 16,432 | 166.94 |

这些数字描述的是切分结果规模和长度，不代表检索质量。A 的总词数会因重叠而增加；C 会在每个块中重复文章标题。B 本次块数最少，但效果也受输入段落格式影响。

要判断哪一种更适合 RAG，需要 M3/M4 使用相同的 embedding 模型、查询集和 top-k 设置建立索引并比较，例如 Recall@k 或 Hit@k、检索延迟和引用相关性。在这项检索实验完成前，不应声称某一种策略的检索效果最好。

## 可复现性

输入文件和参数相同的情况下，chunk ID 和输出内容可复现。M1 更新文档后，再次运行上述命令即可重建三套结果和 manifest。
